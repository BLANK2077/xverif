xdebug - unified xdebug request interface
=========================================

Usage
-----
  xdebug -h
  xdebug -help
      Print this human-readable help and exit with status 0.

  xdebug -
      Read one JSON request from stdin and print one XOUT text response.

  xdebug request.json
      Read one JSON request file and print one XOUT text response.

  xdebug --json -
      Read one JSON request and print the original JSON response.

Request / output contract
-------------------------
  All xdebug capabilities are requested through JSON:

    api_version / request_id / action / target / args / limits

  Default output is token-efficient XOUT structured text. It reduces JSON
  punctuation and repeated structure; readability is a secondary benefit:

    @xdebug.<action>.v1

    summary:
      signal         : top.u.ready
      analysis_complete: true

  The handler base class renders ordinary summary/data blocks. Trace, value,
  scope and protocol handlers add source windows or domain tables. XOUT is a
  compact projection and is not parsed back into JSON. This does not make JSON
  the preferred AI/MCP format. Use --json only for stable-field programming,
  schema validation, structured persistence, deterministic machine comparison,
  exact unprojected nested fields, or an explicit user request. The renderer does not hide
  returned rows: limits and truncation are expressed by the action contract.

  Successful value.at responses use a compact matrix instead:

    @xdebug.value.at.v1

    name         100ns  120ns
    top.u.valid  1'h1   1'h0
    top.u.ready  1'h0   missing_value

  The first column is the signal or semantic alias; subsequent columns follow
  requested time order. Request JSON only when its structured fields are needed.

  Use --json to obtain the JSON object for the structured use cases above.

  Machine-readable help remains available through JSON actions:

    {"api_version":"xdebug.v1","action":"actions"}
    {"api_version":"xdebug.v1","action":"schema","args":{"action":"signal.statistics","kind":"request"}}

Shell setup
-----------
  Use <xverif-root> for your local repository root. Do not hard-code a
  personal machine path in shared docs or scripts.

  Bash (~/.bashrc):

    export XVERIF_HOME=<xverif-root>
    export PATH="$XVERIF_HOME/tools:$PATH"

  Zsh (~/.zshrc):

    export XVERIF_HOME=<xverif-root>
    export PATH="$XVERIF_HOME/tools:$PATH"

  Tcsh (~/.tcshrc):

    setenv XVERIF_HOME <xverif-root>
    setenv PATH "$XVERIF_HOME/tools:$PATH"

Request envelope
----------------
  Minimal request:

    {
      "api_version": "xdebug.v1",
      "action": "actions"
    }

  Typical request:

    {
      "api_version": "xdebug.v1",
      "action": "trace.driver",
      "target": {
        "daidir": "simv.daidir"
      },
      "args": {
        "signal": "top.u.ready"
      }
    }

Target modes
------------
  target.daidir
      Design-side facts. Use for driver/load/query, dependency graph,
      source evidence, expression normalization, FSM/counter/sequential facts.

  target.fsdb
      Waveform-side facts. Use for scopes, values, events, APB/AXI,
      verification windows, signal changes, handshake and anomaly checks.

  target.daidir + target.fsdb
      Combined/debug join mode. Use waveform time and design causality together,
      especially trace.active_driver.

  target.session_id
      Required for all stateful debug queries after session.open.
      session.close accepts only target.session_id; session selection inside
      args is rejected by the strict request schema.

  xdebug never silently switches action, surface, transport, backend, or data
  source after a failure. Obsolete or non-canonical action names return
  UNKNOWN_ACTION. Choose any different route explicitly in a new request.

Session transport
-----------------
  Default transport is UDS. Keep the default for normal same-host debug.
  Set XDEBUG_TRANSPORT=uds|tcp|file to choose the default transport for newly
  opened sessions; explicit session.open args.transport takes priority.
  A transport failure does not trigger automatic switching.

  Use TCP only when UDS sockets are not reachable, for example container or
  namespace boundaries, inaccessible socket paths, or explicitly requested
  remote/cross-process daemon access.

  Local TCP session.open args:
      Set args.transport=tcp with bind_host and port.

    {
      "name": "wave_tcp",
      "transport": "tcp",
      "bind_host": "127.0.0.1",
      "port": 0
    }

  port:0 or omitted lets the daemon choose an available port. bind_host is the
  daemon listen address; host is the client-reachable endpoint address for
  remote/container cases. Do not bind to public addresses unless explicitly
  needed and authorized.

  Use file transport when the client cannot connect to a compute-node TCP port
  but both sides can see the same ~/.xdebug session directory:

    {
      "name": "wave_file",
      "transport": "file"
    }

  file transport stores a v2 state directory under
  ~/.xdebug/{design,waveform}/sessions/<session_id>/transport/:

      requests/    client-published pending requests
      claims/      worker-claimed running requests
      responses/   unread responses
      done/        archived request/claim/response history
      failed/      client_timeout / expired / stale_claim / invalid_request
      tmp/         atomic write temp files
      heartbeat/   worker liveness files

  Request, response and heartbeat files are written via tmp file plus atomic
  publish so readers do not consume half-written files. Old locks/ directories
  from earlier sessions can be ignored.
  File request timeout defaults to 300s and can be changed with
  XDEBUG_FILE_TRANSPORT_TIMEOUT_MS. Ping/quit timeout defaults to 2s and can be
  changed with XDEBUG_FILE_TRANSPORT_PING_TIMEOUT_MS. History is kept by
  default; set XDEBUG_FILE_KEEP_HISTORY=0 to discard successful response
  archives.

Analysis cache memory
---------------------
  XDEBUG_ANALYSIS_CACHE_MAX_BYTES is the soft budget (default 1073741824;
  0 disables proactive soft LRU). XDEBUG_ANALYSIS_CACHE_HARD_MAX_BYTES is the
  mandatory hard limit (default 2147483648; must be positive and >= soft).
  Both values are parsed strictly once when the engine starts. Empty strings,
  signs, whitespace/trailing characters, overflow, hard=0, or soft>hard make
  session startup fail; xdebug does not silently substitute defaults.

Output control
--------------
  Responses are compact by default. Use action-specific args.output.verbose,
  line_limit, or export actions when details are needed. Trace XOUT source windows use
  XDEBUG_TRACE_SOURCE_CONTEXT_LINES (default 3) and merge same-file nearby
  source hits with XDEBUG_TRACE_SOURCE_MERGE_THRESHOLD_LINES (default 10).
  Time-rendering actions use args.render_time_unit=ns|ps|us|auto; the default
  is ns. This parameter changes only canonical response string rendering, not
  parsing, sampling, filtering, ordering, ranges, or active-trace decisions.
  It is available only when the action-specific request schema declares it;
  no synonymous public field is accepted.

Common actions
--------------
  Catalog:
      actions, schema

  Session:
      session.open, session.list, session.doctor,
      session.close, session.gc

  Session close modes:
      session.close defaults to args.mode=graceful. Use args.mode=force only
      for stale or unhealthy state that cannot complete graceful shutdown.

  Design:
      trace.driver, trace.load, expr.normalize

  Waveform:
      scope.list, nwave.rc.generate, value.at, list.load,
      event.find, event.export, verify.conditions, expr.eval_at,
      window.verify, signal.changes, signal.statistics, counter.statistics,
      signal.stability, protocol.handshake.inspect, signal.anomaly.inspect

  Protocol:
      apb.query, apb.export, axi.query, axi.analysis

  Combined:
      trace.active_driver

Action choice guidance
----------------------
  active/high cycles:
      Use signal.statistics. With args.clock it returns clock-sampled
      high_cycles/low_cycles/activity; without args.clock it returns raw
      value-change statistics and sampling_mode explains that behavior.

  counter min/max/average:
      Use counter.statistics with clock, time_range, vld and cnt. cnt may be a
      single signal or a restricted {hi,lo} concat up to 64 bits.

  transition timeline:
      Use signal.changes with mode:"timeline" (the default). line_limit bounds
      data.changes rows. Use mode:"summary" for aggregate facts only; summary
      mode rejects line_limit.

  window holds 0/1:
      Use window.verify, or signal.statistics for sampled activity. Do not use
      signal.changes row counts as cycle counts.

  first/last occurrence:
      Use event.find, or signal.changes with mode:"summary".
      event.find expressions support !, &&, ||, ==, !=, <, <=, > and >=.
      For valid/ready protocols, legal idle/backpressure is not automatically
      a stuck bug; prefer valid-qualified event.find, signal.changes and
      window.verify before using signal.anomaly.inspect as a smoke scan.

Output control
--------------
  Default:
      Compact summary/evidence.

  Detailed output:
      args.output.verbose=true only when the action schema allows it.
      Use action-specific line_limit for bounded rows and export actions for
      complete datasets. Top-level output, output.verbosity, and public
      include_* switches are rejected.

Examples
--------
  List machine-readable actions:

    printf '%s\n' '{"api_version":"xdebug.v1","action":"actions"}' | xdebug -

  Query a design driver:

    printf '%s\n' '{
      "api_version":"xdebug.v1",
      "action":"trace.driver",
      "target":{"daidir":"simv.daidir"},
      "args":{"signal":"top.u.ready"}
    }' | xdebug -

  Open a session, then query it explicitly:

    printf '%s\n' '{
      "api_version":"xdebug.v1",
      "action":"session.open",
      "target":{"daidir":"simv.daidir","fsdb":"waves.fsdb"},
      "args":{"name":"case_a"}
    }' | xdebug -

    printf '%s\n' '{
      "api_version":"xdebug.v1",
      "action":"value.at",
      "target":{"session_id":"case_a"},
      "args":{"signal":"top.clk","time":"10ns"}
    }' | xdebug -

  Join waveform time to active design driver:

    printf '%s\n' '{
      "api_version":"xdebug.v1",
      "action":"trace.active_driver",
      "target":{"session_id":"case_a"},
      "args":{"signal":"top.u.ready","requested_time":"100ns"}
    }' | xdebug -

Logs and troubleshooting
------------------------
  xdebug logs are silent and best-effort. They do not print to stdout/stderr
  and do not change JSON responses.

  Public action logs:
      ~/.xdebug/sessions/<session_prefix>_<hash>/logs/actions.ndjson
      ~/.xdebug/sessions/<session_prefix>_<hash>/logs/stdio.ndjson

  Engine logs:
      ~/.xdebug/engine/sessions/<hashed-session>/logs/lifecycle.ndjson
      ~/.xdebug/engine/sessions/<hashed-session>/logs/transport.ndjson
      ~/.xdebug/engine/sessions/<hashed-session>/logs/crash_marker.ndjson
      log_health.ndjson in each logs/ directory

  MCP direct/LSF logs:
      ~/.xverif/mcp/sessions/<alias>/session.ndjson
      ~/.xverif/mcp/sessions/<alias>/stdio.ndjson
      ~/.xverif/mcp/sessions/<alias>/lsf.ndjson

  SDK-free loop wrapper logs:
      ~/.xverif/loop-wrapper/logs/uds.ndjson
      ~/.xverif/loop-wrapper/sessions/<alias>/session.ndjson
      ~/.xverif/loop-wrapper/sessions/<alias>/stdio.ndjson
      ~/.xverif/loop-wrapper/sessions/<alias>/lsf.ndjson

  Helpers:
      xdebug log doctor --session <id> --json
      xdebug log tail --session <id> --lines 40
      xdebug log bundle --session <id> --out debug_bundle.tgz
      xdebug log bundle --session <id> --out debug_bundle.redacted.tgz --redact

  Troubleshooting order:
      1. Check public actions.ndjson for action, routing, elapsed_ms and error.
      2. Check stdio.ndjson for ready, invalid JSON, validate failure and EOF.
      3. Check lifecycle.ndjson for startup, NPI init, design load, FSDB open,
         daemon ready, timeout, refresh and restart events.
      4. Check transport.ndjson for connect, ping, write, read and timeout.
      5. Check MCP session/stdio/lsf logs for ready timeout, stdout pollution,
         job id, stderr_tail and cleanup.
      6. Check loop-wrapper uds/session/stdio/lsf logs for SDK-free wrapper
         JSONL request parsing, socket handling, LSF job id and cleanup.
